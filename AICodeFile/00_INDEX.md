# ClawFlow / AICodeFile 文档索引（AI 优先）

> 目标：让人和 AI 都能在 1-3 分钟内定位到**架构、目标、计划、当前进度、约定**。

## 读者路径（推荐阅读顺序）

- **首次接入（AI/新同学）**
  - 先读：`01_PROJECT_OVERVIEW.md`
  - 再读：`02_ARCHITECTURE.md`
  - 然后：`04_ROADMAP.md`
  - 最后：`06_TASKS.md`（任务细项/验收/完成记录）

- **要开始干活（实现某个功能）**
  - 先查：`06_TASKS.md`（按模块与优先级）
  - 再看：`05_DEV_PROCESS.md`（统一协作流程/产物要求）
  - 产出记录：`90_LOGS/README.md`（日志格式与写法）

## 文件地图（按用途分层）

### 0) 入口与导航

- `00_INDEX.md`：本文档（索引）
- `01_PROJECT_OVERVIEW.md`：项目总览（目标/范围/术语/关键约束/成功标准）
- `04_ROADMAP.md`：路线图（里程碑与优先级，不含实现细节）

### 1) 架构与技术边界

- `02_ARCHITECTURE.md`：当前架构说明（Main/Preload/Renderer + 内置引擎/网关 + IPC）

### 2) 计划与执行

- `06_TASKS.md`：开发任务清单（任务描述/依赖/验收/完成记录）
- `05_DEV_PROCESS.md`：AI 协作开发流程（输入→设计→实现→验证→交付→留痕）

### 3) 产品与日志

- `03_PRD.md`：PRD/产品策划
- `prototype/`：**HTML 产品原型（静态可点击）**，路径为 `${REPO_ROOT}/AICodeFile/prototype/`（入口 `index.html`）
- `90_LOGS/`：开发日志（按天/按主题记录变更与决策）

## 统一约定（AI 可读性关键）

- **命名规则**：`NN_TOPIC.md`（两位数字 + 全大写英文主题），保持可排序与稳定引用（日期写在文档元信息或日志文件名里）。
- **路径占位符**：文档里不要写死 `E:/ClawFlow`，统一用 `${REPO_ROOT}` 表示仓库根目录。
- **任务描述格式**：尽量包含「目标/非目标/依赖/风险/验收标准/涉及文件」。
- **完成记录**：任务完成后，写入日志并在任务末尾保留 3-7 行的摘要指针（不要把长复盘塞进任务正文）。
