# ClawFlow / AICodeFile 文档索引（以代码为准）

> 目标：让人和 AI 在 1–3 分钟内定位到 **产品是什么 / 已落地什么 / 还缺什么 / 代码在哪里**。

## 推荐阅读顺序

- **首次接入（AI/新同学）**
  - `01_PROJECT_OVERVIEW.md`：项目与范围（一句话理解）
  - `03_PRD.md`：PRD（已落地/未实现/待改进 + 证据）
  - `02_ARCHITECTURE.md`：架构与关键调用链（Main/Preload/Renderer/IPC/引擎/工具）
  - `08_CHAT_SEND_PAYLOAD.md`：对话发送 payload（messages、tools、磁盘路径是否进 API）
  - `04_ROADMAP.md`：路线图（面向下一步）

- **要开始改代码**
  - `06_TASKS.md`：按模块拆分的待办与验收（与 PRD 对齐）
  - `05_DEV_PROCESS.md`：写法与交付要求（保证“有理有据”）

## 文件地图

- `00_INDEX.md`：索引（本文件）
- `01_PROJECT_OVERVIEW.md`：项目总览（目标/术语/关键约束/成功标准）
- `02_ARCHITECTURE.md`：架构说明（含关键文件、数据流、IPC 与安全边界）
- `03_PRD.md`：PRD（从当前代码反推；每条需求带“代码证据”）
- `04_ROADMAP.md`：路线图（里程碑 + 依赖）
- `05_DEV_PROCESS.md`：开发流程（如何写“可追溯”文档与验收）
- `06_TASKS.md`：任务清单（按模块/优先级/验收）
- `08_CHAT_SEND_PAYLOAD.md`：每次对话发往模型的内容与文件（DeepSeek / messages / tools / 工作区路径对照）

## 统一约定（本轮重整理的标准）

- **以代码为单一事实来源**：文档中每个“已实现/未实现”的判断都要给出证据（文件路径 + 关键函数/IPC 名/类型名）。
- **路径占位符**：文档不写死盘符，统一用 `${REPO_ROOT}` 表示仓库根目录。
- **功能状态分类**：
  - **已落地**：仓库内存在代码路径 + 可触发入口（UI 或 IPC 或 Tool）+ 类型/数据模型已定义
  - **部分落地**：有代码/类型，但缺 UI/缺调度/缺广播/缺验收
  - **未实现**：仅有占位或文档设想，无运行路径
