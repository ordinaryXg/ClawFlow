# ClawFlow 文档与开发流程（本轮标准）

> 目标：让“文档”成为可追溯、可验收、可维护的产物，而不是与代码漂移的描述。

## 1. 基本要求（写文档时必须满足）

- **每条结论要能追到代码**：给出 `文件路径 + 关键符号/IPC 名/工具名/数据文件名`
- **明确功能状态**：已落地 / 部分落地 / 未实现 / 待改进（不要含糊）
- **不要用过时设想覆盖现实**：当代码与旧文档冲突时，以代码为准并更新文档

## 2. PRD 写法模板（建议）

每个功能模块用同一结构：

- **用户故事**
- **已落地**（证据列表）
- **未实现/待改进**（证据列表：缺失的入口/缺失的数据/缺失的 IPC/缺失的 UI）
- **验收标准**

## 3. 任务拆分写法（`06_TASKS.md`）

每个任务写清：

- **目标**：一句话
- **范围**：做/不做
- **验收**：可操作的步骤与预期
- **代码落点**：预期改动的文件列表

## 4. 推荐的实现顺序（适用于本项目）

- 先打通链路：Renderer → Preload → Main →（引擎/服务/写盘）
- 再补一致性：广播刷新、调度、边界条件、错误码与用户提示
- 最后补质量门禁：`npx tsc --noEmit`、最小单测/脚本（按里程碑推进）
