# DevelopmentLog 使用说明（AI 可读）

## 目标

把“发生了什么、为什么这么做、影响范围、如何验证”留下可检索的记录，避免只在聊天记录里。

## 存放位置

- **统一写在本目录** `AICodeFile/90_LOGS/`，不要使用 `docs/plans/` 等其他路径（与钩子、提交流程一致）。

## 文件命名建议

- 按日期：`YYYY-MM-DD.md`
- 或按主题：`YYYY-MM-DD_<topic>.md`

## 推荐日志模板（复制即用）

```md
# ClawFlow DevLog - YYYY-MM-DD

## TL;DR

- 3-7 条摘要：做了什么 + 为什么

## 变更内容

- **功能/模块**：
- **涉及文件**：
- **接口/协议变化**（IPC channel / payload / error contract）：

## 决策与权衡

- **决策点**：
- **备选方案**：
- **为什么不选**：

## 验证方式

- [ ] 手动路径：
- [ ] 自动化（lint/typecheck/test）：

## 已知问题 / 后续工作

- ...
```

## 与任务清单的关系

- `06_TASKS.md` 里每个任务的“完成记录”建议只保留短摘要与指针。
- 详细复盘、接口变更、踩坑记录写进 `90_LOGS/`，便于长期检索。
