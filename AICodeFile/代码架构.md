# ClawFlow 代码架构（以当前代码为准）

> **单一事实来源**：`AGENTS.md`、`src/index.ts`、`src/preload.ts`、`src/main/*`、`src/engine/*`。  
> 路径占位符：`${REPO_ROOT}` = 仓库根目录；`${WORKSPACE}` = 用户选定的工作区根目录。

## 1. TL;DR

```
┌─────────────────────────────────────────────────────────────┐
│  Renderer (React 19 + Zustand + react-router HashRouter)     │
│  pages/  components/  store/  ──preload──►  electronAPI      │
└────────────────────────────┬────────────────────────────────┘
                             │ contextBridge (contextIsolation)
┌────────────────────────────▼────────────────────────────────┐
│  Main (Electron)  src/index.ts                               │
│  ├─ main/workspace/   注册表、.agent 引导、Git、技能、清理    │
│  ├─ main/system-agents/  应用缓存内三系统槽位               │
│  ├─ main/todo|scrape|skill|shell|prefs/                     │
│  ├─ engine/           ClawFlow 引擎、Gateway、tool-runtime   │
│  └─ messaging/        飞书 WS + IPC                          │
└────────────────────────────┬────────────────────────────────┘
                             │
         ┌───────────────────┼───────────────────┐
         ▼                   ▼                   ▼
   ${WORKSPACE}/.agent/   userData/          AppCache/
   项目内元数据            注册表/鉴权         workspaces/<hash>/
```

## 2. 进程与入口

| 角色 | 入口 | 构建 |
|------|------|------|
| 主进程 | `src/index.ts` | Webpack `webpack.main.config.ts` |
| 渲染进程 | `src/renderer.tsx` → `App.tsx` | Forge `entryPoints` |
| Preload | `src/preload.ts` | 与 renderer 同捆 |
| 路径别名 | `@/*` → `src/*`，`@main/*` → `src/main/*` | `tsconfig` + Webpack `resolve.alias` |

### 2.1 主进程启动顺序（`index.ts`）

1. `registerMessagingIPC()` — **必须在 `app.whenReady` 之前**（飞书等）。
2. 早期 IPC：窗口外观、工作区 stat/导入、todo、scrape、sticky、应用路径等（避免渲染进程过早 `invoke` 失败）。
3. `registerWorkspaceIPC()` — 工作区、剪贴板、Hermes 技能/记忆、Git 等大段 handler。
4. `registerWindowControlIpcOnce` / `buildBaseBrowserWindow` / `registerStickySatelliteIPC`。
5. `app.whenReady()`：读偏好 → 工作区初始化 → `registerClawFlowIPC` → `registerGatewayIPC` → `registerSystemAgentsIPC` → `createWindow()` → 飞书长连等。

协作说明见仓库根 `AGENTS.md`。

## 3. 目录结构（心智模型）

```
src/
  index.ts, preload.ts, renderer.tsx, App.tsx
  main/
    workspace/          # workspace-service, explorer, blob-store, hermes bootstrap, legacy cleanup
    system-agents/        # 认知分配、预期规划、Skill Agent 槽位与 IPC
    sub-agent/            # 兼容 re-export；sub-agent-runner → system-sub-agent-runner
    skill/                # skill-evolution-scheduler, skill-agent-bootstrap
    todo/                 # 触发器 CRUD、调度、broadcast
    scrape/               # 抓取任务与 runner
    shell/                # 托盘、主壳工作区记忆、UI prefs
    prefs/                # app-cache, messaging, web-search, engine-runtime
    application-menu.ts
    electron-workspace-context.ts   # resolveWorkspaceRootForWebContents
    sticky-satellite-windows.ts
  engine/
    clawflow-engine.ts    # 对话、tool loop、流式、工具审批
    tool-runtime.ts       # 默认工具注册与 manifest 校验
    gateway-daemon.ts
    hermes-memory-db.ts   # SQLite FTS5
    auth-store.ts, session-store.ts, provider-router.ts, web-search.ts
    active-workspace-root.ts
  messaging/              # feishu-event-server, register-messaging-ipc
  components/, pages/, store/, shared/, locales/, workspace-templates/
```

`engine/`、`messaging/` 通过相对路径引用 `../main/...`（非 `@main` 别名时）。

## 4. IPC 与安全边界

### 4.1 命名约定

- Channel：**`领域:动作`**，如 `workspace:listDir`、`engine:sendMessageStream`、`systemAgents:classifyConversation`。
- 工作区相对路径类 API：先 `resolveWorkspaceRootForWebContents(event.sender)` 再访问磁盘。

### 4.2 Preload 暴露面（`window.electronAPI`）

| 前缀 | 职责 |
|------|------|
| `app:*` | 版本、语言、退出/重启、应用缓存根、打开路径、launcher stash 清扫 |
| `window:*` | 最小化/最大化/关闭、DevTools、剪贴板编辑、`setShellViewAppearance` |
| `engine:*` | 会话、发消息流、运行时设置、Web 搜索设置、上下文估算、工具审批 |
| `engineGateway:*` | Gateway 状态/启停/日志 |
| `engineAuth:*` | 多 Provider 鉴权 profile |
| `systemAgents:*` | 分类、预期规划、overview/settings/slots |
| `messaging:*` | 飞书 Bot 配置与发消息 |
| `workspace:*` | 活动工作区、目录读写、Git、manifest、changelog、导入 |
| `sticky:*` | 便签 bootstrap、卫星窗路径 |
| `intelligence:*` | 智能档案、进化测试 |
| `memoryFts:*` | Hermes 记忆搜索/重建 |
| `workspaceSkills:*` | 技能列表/读文件/启用/删除 |
| `todoTriggers:*` | 列表/保存/AI receipt |
| `scrape:*` | 任务列表/读工件 |
| `clipboard:writeText` | 写剪贴板 |

### 4.3 主进程 → 渲染进程事件（节选）

`engine:chatStream`、`workspace:changed`、`workspace:changelogUpdated`、`todo-trigger:fired`、`todo-triggers:updated`、`scrape:jobsUpdated`、`systemAgents:settingsUpdated`、`systemAgents:expectationPlanDelta`、`sticky:detachedPaths`、`chat:conversationsDirty`、`app:navigate`、`embedded-browser:navigate`

### 4.4 安全原则

- Renderer **无 Node.js / 直接 FS**；`contextIsolation` + 受控 `contextBridge`。
- 文件工具路径校验在工作区根内（`tool-runtime` + explorer 层）。
- 敏感鉴权存 `userData/.agent/.clawflow/` 或引擎 auth store，不经由持久化到工作区仓库。

## 5. 数据落盘布局

### 5.1 工作区内（`${WORKSPACE}`）

| 路径 | 内容 |
|------|------|
| `.agent/.tool/manifest.json` | 工具能力开关 v2（`workspace-tools.ts`） |
| `.agent/.tool/*.md` | 各能力说明（缺失时补写） |
| `.agent/.clawflow/` | 主会话元数据、Hermes `hermes-memory.db`、scrape jobs/artifacts 等 |
| `.agent/.skills/` | Hermes 工作区技能目录 |
| `.agent/.memory/` | 主记忆 Markdown 模板与条目 |
| `.agent/.roleAgent/` | 角色 Agent 模板（bootstrap） |
| `.clawflow-data/` | **待办触发器**（重置 `.agent` 时不删） |

打开工作区时：`migrateLegacyWorkspaceAgentBundleSync`、清理遗留 `.subagent/`（`workspace-legacy-subagent-cleanup.ts`）。

### 5.2 应用缓存（`AppCache/workspaces/<sha256>/`）

| 路径 | 内容 |
|------|------|
| `.clawflow-launcher-stash/` | 启动器暂存（**不**随 Git 同步） |
| `workspace-root.txt` | 绑定的工作区绝对路径 |

系统级子 Agent 与名册：`{appCache}/system/.subagent/`、`.clawflow/sub-agents.v1.json`（`system-agent-layout.ts`）。

### 5.3 userData（Electron `app.getPath('userData')`）

- `cf.workspace.v1.json` — 最近工作区注册表
- `cf.app-cache-prefs.json` — 自定义应用缓存根
- 全局引擎鉴权、会话索引（逐步迁移至工作区 `.agent/.clawflow`）

## 6. 引擎与工具治理

### 6.1 ClawFlow Engine（`clawflow-engine.ts`）

- 维护 Provider 路由、会话存储、**tool loop**（模型返回 tool_calls → `ToolRuntime` 执行 → 再喂回模型）。
- 发送前：`filterToolSchemasByWorkspaceManifest`（`workspace-tool-manifest-bridge.ts`）。
- 执行时：`toolNameAllowedByWorkspaceManifest` 二次拒绝已禁用能力（`tool-runtime.ts`）。
- 流式经 IPC `engine:chatStream` 推送到渲染进程；敏感工具可走 `engine:resolveToolApproval`。

### 6.2 Tool Runtime 工具清单

共 **34** 个内置工具名（`tool-runtime.ts`），分组：

- 通用：`get_date`、`web_search`、`open_embedded_browser`、`web_scrape`
- 文件：`workspace_list_dir`、`workspace_read_file(_preview)`、`workspace_write_file`、`workspace_apply_patch(_v2)`、`workspace_mkdir`、`workspace_rename_path`、`workspace_delete_path`、`workspace_rollback_op`
- 执行：`workspace_run_shell`、`workspace_run_tsc_no_emit`
- Git/搜索：`workspace_git_*`、`workspace_rg_search`
- 待办：`workspace_todo_*`
- 知识/记忆/技能：`workspace_knowledge_query`（stub）、`workspace_memory_*`、`workspace_skill_*`

**已移除**：工作区 `workspace_subagent_*`、OpenClaw `openclaw_skills_list` 等。

### 6.3 Manifest 能力 ID

`docs` | `git` | `shell` | `web_search` | `web_scrape` | `embedded_browser` | `todos` | `skills` | `knowledge_base`

v1 兼容：manifest 中单独 `browser` 键会同时映射三项浏览器相关能力。

## 7. 系统 Agent 架构

三个固定槽位（`system-agent-constants.ts`），数据与模板在 **应用缓存**，不占工作区 `.subagent/`：

| 槽位 ID | 职责 |
|---------|------|
| `cf-skill-agent` | Skill 进化与维护（`skill-evolution-scheduler.ts`） |
| `cf-cognitive-allocation` | 发送前 M1–M5 模式分类 |
| `cf-expectation-planning` | 复杂任务步骤规划（流式 delta：`systemAgents:expectationPlanDelta`） |

运行入口：`system-sub-agent-runner.ts`（`sub-agent-runner.ts` 仅 re-export，并注明工作区委派已移除）。

## 8. Hermes 子系统

| 组件 | 文件 | 说明 |
|------|------|------|
| 记忆 DB | `hermes-memory-db.ts` | `${WORKSPACE}/.agent/.clawflow/hermes-memory.db` + FTS5 |
| 索引钩子 | `hermes-memory-index-hooks.ts`、`hermes-skill-index-hooks.ts` | 文件变更后 best-effort 重建 |
| 技能引导 | `workspace-hermes-skill-bootstrap.ts` | 确保 `skill-creator/SKILL.md` |
| IPC | `memoryFts:*`、`workspaceSkills:*` | 设置页与 Skills 页 |

## 9. 横切能力

| 能力 | 主模块 |
|------|--------|
| Gateway | `gateway-daemon.ts`，默认 `127.0.0.1:18789` HTTP+WS |
| 飞书 | `messaging/feishu-event-server.ts` + `register-messaging-ipc.ts` |
| 待办调度 | `todo-triggers-scheduler.ts` + `cron-parser` |
| 网页抓取 | `scrape-runner.ts` → `.agent/.clawflow/scrapes/*.md` |
| 便签卫星窗 | `sticky-satellite-windows.ts` |
| Shell 执行 | `workspace-shell-exec.ts`（工作区根内命令） |

## 12. 演进建议（架构债）

- `index.ts` 体积过大：可按域迁至 `src/main/ipc/`（`AGENTS.md` 已注明）。
- `workspace-agent-layout.ts` 头部注释仍含历史 `.subagent/` 布局，与运行时「清理 + 系统缓存」并存，阅读时以 `workspace-legacy-subagent-cleanup.ts` 为准。
- 知识库 Retriever、部分 messaging 渠道仍为占位，架构上预留 manifest 键与 stub 工具。
