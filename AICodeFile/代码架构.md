# ClawFlow 代码架构（以当前代码为准）

> **单一事实来源**：`README.md`、`src/index.ts`、`src/preload.ts`、`src/main/*`、`src/engine/*`。  
> 路径占位符：`${REPO_ROOT}` = 仓库根目录；`${WORKSPACE}` = 用户选定的工作区根目录。


## 2. 进程与入口

| 角色 | 入口 | 构建 |
|------|------|------|
| 主进程 | `src/index.ts` | `webpack.main.config.ts` |
| 渲染进程 | `src/renderer.tsx` → `App.tsx` | Forge `entryPoints` |
| Preload | `src/preload.ts` | 与 renderer 同捆 |
| 路径别名 | `@/*` → `src/*`，`@main/*` → `src/main/*` | Webpack + `tsconfig` |

### 2.1 主进程启动顺序（`index.ts`）

1. `registerMessagingIPC()` — **必须在 `app.whenReady` 之前**。
2. **模块加载时尽早注册**（`main/ipc/`）：
   - `registerShellViewWindowIPC`
   - `registerWorkspaceEarlyIPC`（import / copyChatDrop / statAbsolutePath）
   - `registerAppPathAndIconIPC`
   - `registerScheduleTriggersIPC`、`registerScrapeIPC`、`registerSystemAgentsIPC`（经 `register-scheduling-scrape-ipc` 等）
   - `registerStickySatelliteIPC`（依赖 `buildBaseBrowserWindow`）
3. `app.whenReady()`：
   - `loadMainUiPrefsOnStartup`
   - 工作区迁移/初始化 → **`applyActiveWorkspace`**（勿手写 `setActiveWorkspace` + `syncActiveWorkspaceRootToEngine` 双调用）
   - `registerWorkspaceIPC()`（大段 workspace / Hermes / Git handler）
   - `registerClawFlowIPC`、`registerGatewayIPC`
   - `registerAppSettingsIPC`（版本、缓存根、语言）
   - `createWindow()`、飞书长连等。
4. 窗口首次创建时：`registerWindowControlIpcOnce`。

详见根目录 `README.md`。

## 4. IPC 与安全边界

### 4.1 命名约定

- Channel：**`领域:动作`**。
- 工作区路径类 API：`resolveWorkspaceRootForWebContents(event.sender)`。

### 4.2 Preload 暴露面（`window.electronAPI`）

| 前缀 | 职责 |
|------|------|
| `app:*` | 版本（`getAppVersion` 为主；`getVersion` 已 deprecated）、语言、缓存根、路径 |
| `window:*` | 窗口、剪贴板、`setShellViewAppearance` |
| `engine:*` | 会话、`sendMessage`、**`estimateNextRequestContext`**、运行时设置、`resolveToolApproval` |
| `engineGateway:*` | Gateway 状态/启停/日志（**聊天依赖**） |
| `engineAuth:*` | 鉴权 profile |
| `systemAgents:*` | 分类、预期规划 |
| `messaging:*` | 飞书 |
| `workspace:*` | 活动工作区、`setActive`、文件、Git、changelog |
| `knowledge:*` | 知识库清单、新建笔记、摄入 |
| `sticky:*` | 便签卫星窗 |
| `memoryFts:*` | Hermes FTS（设置页） |
| `workspaceSkills:*` | 技能列表/读写 |
| `scheduleTriggers:*` / `scrape:*` | 周期调度、抓取 |

Gateway 旧别名：`getGatewayStatus` / `startGateway` / `stopGateway` → 委托 `engineGateway*`（deprecated）。

### 4.3 主进程 → 渲染进程事件（节选）

`workspace:changed`、`workspace:changelogUpdated`、`schedule-trigger:fired`、`schedule-triggers:updated`、`scrape:jobsUpdated`、`systemAgents:settingsUpdated`、`systemAgents:expectationPlanDelta`、`sticky:detachedPaths`、`chat:conversationsDirty`、`app:navigate`

**聊天流式（主路径）**：经 Gateway WebSocket 帧（`chat:delta` / `chat:final` / `chat:toolApproval`），非 `engine:chatStream`。

`engine:chatStream` 仍可由 `engine:sendMessageStream` 发出，但 **chatStore 未订阅**。

### 4.4 安全原则

- Renderer 无 Node/直接 FS；`contextIsolation` + `contextBridge`。
- 工具路径在工作区根内校验（`tool-runtime-core.ts` + explorer）。
- 鉴权存 userData / 引擎 auth store，不写进用户 Git 工作区。

## 6. 引擎与工具治理

### 6.1 ClawFlow Engine（`clawflow-engine.ts`）

- Provider 路由、会话、`tool loop`。
- Manifest 过滤 + 执行二次校验。
- **聊天输出到 UI**：
  - **主路径**：`GatewayDaemon` WS → `chat-gateway-client.ts`。
  - **回退**：`engine:sendMessage`（非流式 IPC）。
  - **遗留 IPC 流**：`engine:sendMessageStream` + `engine:chatStream`（UI 未接）。
- 工具审批：引擎 `resolveToolApproval`；UI 经 WS `chat:toolApprovalResponse`。
- 上下文估算：`estimateNextRequestContext` ↔ `next-request-context.ts`（与 `buildHistoryMessages` 共用 `composeNextRequestChatMessages`）。

### 6.2 Tool Runtime

- **36** 个内置 `function.name`（`tool-runtime-default-tools.ts`）。
- 检索类：**优先 `hermes_search`**；`workspace_knowledge_query` / `workspace_memory_search` 为 deprecated 包装。
- 飞书：`workspace_feishu_invoke` → `main/lark-cli/`。

### 6.3 Manifest 能力 ID

`docs` | `git` | `shell` | `web_search` | `web_scrape` | `todos` | `skills` | `knowledge_base`

v1 `browser` 键仍映射 `web_search` + `web_scrape`。
